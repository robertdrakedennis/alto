# recorded

Recordings of the original client's observable behaviour: output streams
(packet bytes, component and variable state, draw traces, pixels, stacks)
that a behaviour oracle produced once for a fixed input corpus. The port's own
test builds the same input and compares its output stream with the recording,
so the default suite needs no other runtime and no original client sources. The
recordings are data, not source: no source text of the original client is kept here.

`rs910_core::test_support::frozen` reads them (`assert_stream`, `text`,
`bytes`). A recording of at most 256 KiB is stored verbatim as `<name>.bin`
(or under its own file name for text corpora); a group that holds one stream
names it `recording`. A larger one is stored as
`<name>.blk`: a first line `len=<bytes> block=<bytes>`, then one FNV-1a 64
digest (16 hex digits) per block of that size. A mismatch names the byte offset
of the first differing block. The block size doubles until a recording has at
most 4096 blocks.

Recordings that hold pixels or cache-derived asset content (icon renders,
sprite/text quads, cursor and font data, object and BAS definitions) are
stored as `.blk` digests only, whatever their size; behaviour streams (packets,
states, matrices, numbers) may be stored verbatim. Inputs that come from the
cache are read from `server/data/pack` by the tests, not stored here.

The recordings were made outside this repository (the harnesses are not
kept here); they are not regenerated by the build.
