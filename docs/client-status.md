# Client status

What the Rust client does today and what is still partial. This replaces the
long per-feature ledger of the porting phase (kept local-only by the
maintainers). It is a summary, not a completion percentage: a feature counts as
done when its real input, network path and presentation are connected, not when
a parser or an isolated test exists.

Status words: **works** (installed in the ordinary client and covered by a
replay, golden or recorded fixture), **partial** (usable, with named gaps),
**open** (not started or only scaffolding).

## Summary

The modern renderer captures owned scene inputs after the main thread finishes
logic and UI preparation. One bounded render thread draws and submits the prior
frame while the next is prepared; interface GPU storage alternates between two
slots, and resize, toolkit changes, screenshots and recovery consume pending
frames before changing their resources. Persistent minimap textures stay registered
in both interface slots when they are created or released. Installed light grids
and point-shadow faces retain their identity across owned frames while each frame
keeps its light values. Unchanged graphics and canvas preferences preserve pending rendering;
resource changes still wait.
Map workers also prepare live-scene construction and animation assets before
handoff. The owner validates the map generation and binds current variables
before activation and acknowledgment. Modern terrain, static meshes and materials
use a bounded priority queue separate from frame work; terrain uploads in chunks,
and all three share the frame's installation time allowance. Ready models draw
with a lit white texture while material decoding finishes. Static geometry and
new maps transition over 250 ms; opaque coverage remains solid and shadow passes
use the same fade. Missing material groups retry after matching JS5 arrivals,
and lighting captures wait for residency and completed transitions. Texture
materials still upload complete mip chains, and derived asset caching and residency budgets
remain future loading work.

See [renderer ownership](renderer/modern-renderer.md#owned-frames-and-render-thread-handoff).

Modern graphics also has local persisted presets and live quality controls in
the native Graphics flow. Device, scene, frame, history and preparation owners
feed an immutable encoding view; the shared CPU scheduler uses safe scoped
Rayon work with ordered results and inline mode. Native ClientOptions and
recorded input semantics retain their existing contract.

Modern water now uses dedicated vertex pigment, bounded world-anchored flow,
restrained filtered ripples, soft planar reflections and depth-dependent absorption.
The shoreline and caustics share the surface gradient; the ordinary material
texture and HDR gain no longer colour the river. GPU checks cover reflection
geometry, depth shading and animation-clock continuity.

## Where verification lives

Four thin checks decide whether behaviour is preserved:

1. Packet encode and decode byte equality.
2. Client options codec and clamping.
3. Movement and variable state per tick.
4. CS2 stack, branch and variable semantics.

They run in the ordinary `cargo test` against
committed recordings (see [`engineering.md`](engineering.md)). Pixel
comparisons are pre-release checks, not part of the fast suite.
